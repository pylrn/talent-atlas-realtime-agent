# Talent Atlas demo deployment

The production demo is one FastAPI container. It serves the public journal,
Talent UI, settings, tool runner, and API from the same origin:

- `/journey` - public project journal
- `/talent` - recruiter UI
- `/talent/settings` - model settings
- `/talent/tool-runner` - tool inspection UI
- `/docs` - API reference
- `/health` - database and service health

`render.yaml` describes a single-worker Render service intended for one or two
concurrent demo users. The Starter plan is intentional: the local embedding and
cross-encoder models need more memory than a small static site.

## Deploy

1. Push this repository to GitHub.
2. Open
   `https://render.com/deploy?repo=https://github.com/pylrn/hybrid-search/tree/feat/personalization-hints`.
3. Enter the secret values requested by the Blueprint:
   `DATABASE_URL`, `DEEPSEEK_API_KEY`, `GROQ_API_KEY`, and
   `APP_DEMO_PASSWORD`.
4. Deploy the Blueprint.
5. Open `https://<service>.onrender.com/journey`.

Do not paste secrets into `render.yaml` or commit a local `.env` file. The
database must contain 384-dimensional embeddings generated by
`all-MiniLM-L6-v2`, matching the container configuration.

## Access control

The journal and health check stay public. When `APP_DEMO_USERNAME` and
`APP_DEMO_PASSWORD` are both set, browsers request those credentials before
opening the Talent UI or API. This protects model credits, uploads, settings,
and recruiter data. Leaving either value unset preserves the current local
development behavior.

## Optional observability

Langfuse is disabled in the Blueprint until its keys are added as Render
secrets. To enable it, set:

```text
LANGFUSE_ENABLED=true
LANGFUSE_PUBLIC_KEY=...
LANGFUSE_SECRET_KEY=...
LANGFUSE_BASE_URL=https://<your-region>.cloud.langfuse.com
```
